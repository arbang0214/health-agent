# Evals — AI 코치 품질 측정

유닛 테스트(`src/lib/__tests__`)는 하네스 로직만 검증한다. 여기의 eval은 **모델이 실제로
어떤 코칭을 생성하는지**를 측정한다 — 실 API를 호출하므로 비용이 들고 결과가 확률적이다.

## 실행 (수동 전용 — CI에 넣지 말 것)

```bash
npm run eval:coach              # 코치 품질 8사례
npm run eval:coach -- goal-5k   # 특정 사례만
```

`.env.local`의 `ANTHROPIC_API_KEY`를 사용한다. 1회 전체 실행 ≈ 16회 API 호출(코치 8 + judge 8).

## 구조

- `coach-cases.ts` — 사례 fixture + rubric. **"코치가 어떻게 망가질 수 있나"** 기준으로 설계:
  - `goal-*` 4사례: 목표 무시, 이전 목표 고착, 칼로리 중심 회귀
  - 일반 품질 4사례: 부상 무시, 과훈련 방치, 데이터 부족 과잉 단정, 공백 무시
- `judge.ts` — LLM-as-judge. 항목별 **이진 판정**(기준은 사례에 사람이 명시)
- `run-coach.ts` — 러너. 운영 route.ts와 동일 조건(model/effort)으로 코치를 호출

## 판정 방식 2종

| 방식 | 예 | 특성 |
|---|---|---|
| 코드 채점 | 3섹션 형식, 목표 거리 언급(정규식) | 결정적·무료 |
| judge 채점 | "코칭의 중심이 목표 달성인가" | 열린 품질 측정, 기준문(criterion) 필수 |

## 기준선 (변별력 증명)

목표 인지 기능 **구현 전** 실행 시 `goal-*` 사례가 실패해야 정상이다 — 실패하지 않는다면
eval이 목표 인지 여부를 구별하지 못한다는 뜻. 구현 후 재실행해 통과로 바뀌는 것까지 확인한다.

프롬프트(`coach-prompt.ts`)를 수정할 때마다 배포 전에 실행해 회귀를 확인한다.
운영 중 이상한 코칭을 발견하면 그 상황을 사례로 추가한다 (버그 리포트 → 회귀 테스트).
